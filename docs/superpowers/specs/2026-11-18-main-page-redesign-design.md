# Редизайн основной страницы: «Кабинет» (вариант A)

Дата: 2026-11-18
Статус: макет на согласовании

## Зачем

Текущая главная (`#dashboard`) — это одна колонка: шапка, сетка комнат и админ-панель
под ней. Ученик, учитель и администратор видят почти одинаковый экран, хотя задачи у них
разные. Администратор при этом видит «Пока нет комнат», хотя комнаты есть — они спрятаны
во вкладке админки. Управление комнатой смешано с просмотром, а создание и переименование
идут через системные `prompt`/`confirm`.

Цель редизайна — сделать главную интуитивной: на каждом экране одно очевидное действие
и только те возможности, которые доступны роли.

## Границы

Входит:

- главная страница после входа: комнаты, ролевые состояния ученика/учителя/администратора;
- создание комнаты, выдача доступа, переименование и удаление — в понятных диалогах;
- админский раздел пользователей как отдельная страница;
- адаптив до мобильного, клавиатурная доступность, понятные пустые состояния.

Не входит:

- экран комнаты/доски (следующий этап);
- новые серверные возможности: превью досок, расписание, онлайн-статусы, счётчики
  учеников в списке комнат;
- изменение API и схемы данных.

## Ограничения

- Данные списка комнат: `id`, `name`, `owner {id, name}`. Ничего больше не показываем
  как факт.
- Роли: ученик видит только выданные комнаты; учитель — свои; администратор — все
  (`GET /api/rooms/all`) и управление пользователями.
- Фронтенд без сборки: HTML/CSS/vanilla JS.
- Интерфейс на русском, существующие названия действий сохраняем, где они понятны
  («Доступ», «Открыть», «Создать комнату»).

## Рассмотренные варианты

- **A. «Кабинет» — ролевая главная с боковой навигацией.** Выбрано.
- B. «Полка комнат» — крупные карточки с превью досок. Требует превью, которых нет,
  и прячет управление в меню.
- C. «Чистый лист» — косметический рефреш текущей одноколоночной страницы. Не решает
  ролевую путаницу и админку под списком.

## Структура

### Каркас

- Слева — светлая боковая панель 264 px: логотип, навигация, подсказка, карточка
  пользователя с выходом. На мобильном превращается в верхнюю панель.
- Справа — рабочая область с мягким серо-голубым фоном, ограничением ширины и
  заголовком страницы.
- Одна первичная кнопка в шапке страницы.

### Роли

**Ученик.** Заголовок «Мои занятия», подпись «Комнаты, которые открыл для вас учитель».
Кнопки создания нет. На карточке — учитель и одна кнопка «Войти в комнату». Никаких
меню управления. Пустое состояние: «Попросите учителя выдать доступ» и кнопка «Обновить».

**Учитель.** Заголовок «Мои комнаты». Одна первичная кнопка «Создать комнату» в шапке
страницы. Карточка: «Открыть», «Доступ», меню `⋯` с «Переименовать» и «Удалить».
Пустое состояние ведёт к созданию первой комнаты.

**Администратор.** Заголовок «Все комнаты»: показывает комнаты всех учителей, с именем
владельца. В навигации — «Все комнаты» и «Пользователи» с бейджем заявок. Управление
доступом, переименование и удаление доступны как у учителя.

### Карточка комнаты

- цветной значок доски (акцент подбирается по индексу);
- название комнаты;
- строка владельца: «Учитель: Софья» / «Вы — владелец»;
- нижний ряд действий, одинаковый по расположению у всех ролей;
- меню `⋯` только там, где есть управление.

### Диалоги

- **Создать комнату**: поле «Название», подсказка, «Отмена» / «Создать комнату».
- **Доступ**: поиск ученика, список с чекбоксами и аватарами, счётчик выбранных,
  «Отмена» / «Сохранить».
- **Переименовать**: поле с текущим названием.
- **Удалить**: подтверждение с названием комнаты и предупреждением о необратимости.

### Админский раздел

Страница «Пользователи»: фильтры «Все / Заявки / Активные / Заблокированные», поиск,
строки с именем, логином, ролью, статусом и действиями. Заявки визуально выделены,
у навигации — бейдж с количеством.

## Визуальный язык

- Фон рабочей области `#f4f7fb`, поверхности `#ffffff`, границы `#e6ebf2`.
- Текст `#0f172a`, вторичный `#64748b`.
- Акцент `#2563eb`, мягкий акцент `#e8efff`, успех `#15803d`, опасность `#b91c1c`.
- Радиусы 10/14/18 px, тени мягкие, без тяжёлых рамок.
- Шрифт: Inter / Segoe UI / системный стек; заголовок 30 px, название карточки 16.5 px,
  основной текст 13–15 px.
- Иконки — встроенный SVG, без внешних зависимостей.
- Подсказки в боковой панели объясняют следующий шаг роли.

## Доступность и адаптив

- Видимый `:focus-visible`, навигация с клавиатуры, `Esc` закрывает диалоги.
- Кнопки не меньше 40×40 px на десктопе; на мобильном основные кнопки — 44 px,
  иконки — 40×40 px.
- Сетка карточек: 3 колонки → 2 → 1.
- На ширине до 900 px боковая панель становится верхней, навигация — горизонтальной.

## Что остаётся разработчику

- Сохранить текущие API-вызовы и права; новые поля не добавлять.
- Реализовать диалоги вместо `prompt`/`confirm`, включая состояния загрузки и ошибки.
- Подключить поиск по названию и владельцу на клиенте.
- Для администратора загружать `GET /api/rooms/all`; действия — через существующие
  эндпоинты.
- Перенести токены и компоненты в `frontend/css/style.css`, не ломая экран комнаты.
