# Вставка изображений из буфера и экспорт воркспейса в PDF

Дата: 2026-11-17. Статус: на согласовании.

## Зачем

Учителю нужно быстро добавлять скриншоты на доску и сохранять итог урока в PDF.
Сейчас картинка вставляется только через файловый диалог, а экспорта доски нет.

## Цели

1. `Ctrl+V`/`Cmd+V` вставляет изображения из буфера обмена.
2. Учитель/администратор скачивает текущую страницу (воркспейс) в PDF.

## Не-цели

- Вставка текста/HTML из буфера.
- Экспорт всех страниц комнаты одним файлом.
- Векторный PDF с выделяемым текстом.
- Серверная генерация PDF.
- Вставка изображений из буфера, когда фокус в поле ввода или редакторе текста.

## Поведение

### Вставка из буфера

- Слушатель `paste` на `document`.
- Если фокус в `INPUT`/`TEXTAREA`/`SELECT`, в `contentEditable` или открыт редактор
  текста — событие не перехватывается.
- Из `clipboardData.items` берутся все файлы `image/*`; при отсутствии — обычное
  поведение браузера.
- Каждый файл загружается через существующий `POST /api/upload`; ошибки показываются
  тостом, остальные файлы продолжают обрабатываться.
- Картинка вписывается в максимум 480 px по ширине (как сейчас), ставится в центр
  доски; несколько картинок смещаются каскадом на 24 px.
- После вставки выделяется последняя картинка и включается инструмент «выбор».
- Доступно всем участникам — как и кнопка «Картинка».

### PDF

- Кнопка `#pdf-btn` в тулбаре видна только учителю и администратору.
- Экспортируется текущая страница; файл:
  `whiteboard-<имя-страницы>-YYYYMMDD.pdf` (недопустимые символы заменяются).
- Формат страницы — **по пропорциям доски** (1600×900 → страница 960×540 pt),
  без полей и без сетки.
- В PDF попадают объекты доски: штрихи, фигуры, текст, блок-схемы, стрелки,
  фреймы, картинки. Не попадают: курсоры, выделение/Transformer, значки замка,
  сетка, интерфейс.
- Рендер — снимок доски в 2× разрешении (3200×1800), JPEG quality 0.92,
  встроенный в PDF как `/DCTDecode` изображение.
- Пустая страница: тост «На странице нет объектов», файл не создаётся.
- Во время рисования экспорт не запускается.
- Если canvas «испорчен» внешним изображением без CORS, показывается тост об ошибке.

## Подходы к PDF

1. **Снимок Konva + собственный минимальный PDF-writer** — выбрано. Без новых
   зависимостей, результат совпадает с доской; минус — растровый текст.
2. jsPDF с CDN/вендорингом — лишние ~350 КБ, результат тот же растровый.
3. Серверный векторный PDF — дублирование отрисовки и новая Python-зависимость;
   избыточно для текущей задачи.

## Реализация

- `frontend/js/export.js`:
  - `pdfPageSize(width, height)` — 960 pt по ширине, высота по пропорциям;
  - `buildPdf(jpegBytes, { pixelWidth, pixelHeight, pageWidth, pageHeight })` —
    минимальный PDF 1.4 с одной страницей и JPEG XObject;
  - `exportWorkspacePdf(board, name)` — получить canvas, JPEG, PDF и скачать файл.
- `frontend/js/board.js`: метод `exportCanvas()` — временно скрыть overlay,
  Transformer, сетку и значки замка, отключить тень бумаги, выставить stage
  1600×900 при scale=1, отрисовать, затем восстановить состояние и `fit()`.
- `frontend/js/main.js`:
  - общий `uploadImageFile(file)` для кнопки и буфера;
  - `handlePaste(event)`, `exportPdf()`;
  - видимость `#pdf-btn` по роли.
- `frontend/index.html`, `frontend/css/style.css`: кнопка PDF.
- Backend не меняется.

## Тесты

- E2E `clipboard-pdf.spec.js`:
  - синтетический `ClipboardEvent` с PNG → на доске появляется image-объект;
  - учитель скачивает PDF: заголовок `%PDF-`, `MediaBox` с пропорциями 16:9;
  - ученик не видит кнопку PDF.
- Полный E2E-набор и backend-тесты остаются зелёными.

## Риски

- Растровый PDF: текст не выделяется и не ищется.
- Большая доска 3200×1800 в памяти: ~23 МБ на canvas, допустимо.
- Внешние S3-изображения без CORS могут «испортить» canvas; в текущем
  production используются локальные uploads, поэтому риск не проявляется.
- Вставка из буфера зависит от того, что браузер отдаёт файл в `paste`;
  для скриншотов Chrome/Edge/Firefox это работает.
