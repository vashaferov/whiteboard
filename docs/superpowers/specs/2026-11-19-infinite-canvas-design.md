# Бесконечный холст и авторазмер презентаций: дизайн

**Дата:** 2026-11-19
**Статус:** решения согласованы с пользователем, дизайн на утверждении
**Контекст:** новый UI комнаты «Студия» уже реализован на `main`; движок доски,
протокол объектов и презентации переиспользуются.

## Зачем

Обычная страница сейчас — белый лист фиксированного размера (по умолчанию
1600×900), вписанный в окно. На планшете и при работе с большими схемами места
не хватает: холст ограничен краями листа, панорама прижимается к ним, а
«Размер холста» задаёт один размер на всю комнату.

Нужен «бесконечный» холст для обычных страниц: рисовать и раскладывать объекты
можно в любую сторону, вид приближается/отдаляется и свободно панорамируется.
Презентации — исключение: там холст должен подстраиваться под размер слайда,
чтобы не было полей и лишних краёв.

## Решения пользователя

1. PDF с бесконечной страницы экспортирует **границы контента** с отступом.
2. «Размер холста» становится **режимом страницы**: бесконечная или фиксированная.
3. Холст презентации **подгоняется на клиенте** по натуральному размеру слайда.
4. Существующие страницы **сразу открываются бесконечными**.
5. Старые пометки на презентациях **не требуют сохранения** при смене размера.

## Режимы страницы

Каждая страница (workspace) получает метаданные:

```json
"canvas": { "mode": "infinite" }
"canvas": { "mode": "fixed", "width": 1200, "height": 800 }
```

- `infinite` — режим по умолчанию для новых и существующих страниц.
- `fixed` — прежняя белая страница с полями; размеры 640–4000, отношение сторон
  до 1:4. Включается вручную в панели «Холст страницы».
- Презентации (`kind: "presentation"`) игнорируют `canvas`: их размер задаёт
  текущий слайд. Панель размера для них скрыта.
- Старые снимки без `canvas` нормализуются в `infinite`. Поле `room.board`
  остаётся только как историческое хранилище для совместимости БД и больше
  не влияет на страницы.

## Вид и навигация

### Бесконечная страница

- **100% = 1 мировой пиксель = 1 CSS-пиксель.** Диапазон зума 10–400%.
- Панорама не ограничена краями; колесо, `Space`/средняя кнопка/протяжка пустого
  места и два пальца работают как сейчас.
- «Вписать» (кнопка `#zoom-reset` по клику и клавиша `0`) вписывает **границы
  всех объектов** с отступом 10% (не меньше 40 мировых px).
- Пустая страница открывается на 100% с центром в точке (800, 450) — там, где
  была старая доска 1600×900, поэтому существующие объекты сразу видны.
- Белая «страница» и её тень не рисуются. Фон — мягкий фон доски; точечная сетка
  рисуется по всему видимому окну в мировых координатах и не влияет на экспорт.
- При перезагрузке/входе вид не сохраняется (как сейчас); после переключения
  страниц вид сбрасывается на «вписать содержимое».

### Фиксированная страница

- Сохраняется прежнее поведение: белый лист с тенью и сеткой, 100% = «вписать
  лист», панорама ограничена 25% листа в окне.

### Презентация

- При показе слайда клиент загружает JPEG, берёт его натуральные `width/height`
  и временно включает фиксированный холст этого размера; слайд занимает его
  целиком, сетка и тень скрыты.
- «Вписать» показывает слайд полностью; зум и панорама доступны ученику.
- При смене слайда размер пересчитывается, вид сбрасывается на «вписать».
  Ошибка загрузки — откат к 1600×900.
- При выходе из презентации восстанавливается режим страницы и «вписать
  содержимое».
- Пометки старых презентаций могут сместиться относительно нового размера —
  это согласовано; данные не удаляются.

## Экспорт PDF

- Область экспорта — объединённые границы всех объектов страницы плюс отступ
  32 мировых px (не меньше 3% от большей стороны).
- Пустая страница не экспортируется (как сейчас).
- Ширина страницы PDF остаётся 960 pt, высота — по пропорциям области.
- Растр снимается при масштабе 1 и origin в левом верхнем углу области; сетка,
  курсоры, выделение, бейджи замка и тень скрываются. Если растр больше
  8000 px по стороне, `pixelRatio` уменьшается, чтобы не переполнить canvas.
- Экспорт не зависит от текущего зума и панорамы.

## Сервер, данные и протокол

- `normalize_workspaces` сохраняет и валидирует `canvas`; отсутствующий блок →
  `{"mode": "infinite"}`. `default_workspace()` сразу создаётся бесконечной.
- Новое сообщение клиент→сервер `workspace_canvas {mode, width?, height?}`
  действует на **текущую страницу**. Только staff; проверка диапазонов и
  пропорций; для `fixed` обязательны `width` и `height`.
- Сервер обновляет `workspace["canvas"]`, помечает комнату грязной и рассылает
  `workspace_canvas {workspaceId, canvas}` участникам этой страницы.
- Снимки и Redis уже хранят произвольные поля workspace, поэтому отдельная
  миграция БД не нужна; меняется только нормализация.
- Старое сообщение `board_resize` и `init.board` больше не используются и
  удаляются из протокола; `Snapshot.board`/`Room.board` остаются ради
  совместимости старых файлов и игнорируются.
- Лимит координат объектов поднимается с ±20 000 до ±1 000 000: этого достаточно,
  чтобы холст ощущался бесконечным, и точность float64 остаётся высокой.

## UI

- В меню «Ещё» пункт «Холст страницы» открывает панель:
  - переключатель «Бесконечный холст» (включён по умолчанию);
  - при выключении — ширина/высота и пресеты 16:9, 4:3, A4, 1:1;
  - «Применить» отправляет `workspace_canvas` и закрывает панель.
- На презентации пункт скрыт; на мобильном панель доступна в том же меню.
- Подпись процента зума остаётся; на бесконечной странице 100% означает
  реальный масштаб, а «вписать» может показать, например, 63%.

## Рассмотренные альтернативы

1. **Огромная фиксированная доска (например 100 000×100 000)** вместо
   бесконечности — визуально похожа, но остаётся листом с краями, ломает
   «вписать по контенту» и требует тайлинга. Отклонено.
2. **Хранить размер каждого слайда на сервере** — строже, но меняет формат
   презентаций и снимки; натуральный размер уже известен клиенту. Отклонено.
3. **Оставить «Размер холста» на комнату** — несовместимо с разными режимами
   страниц и автоподгонкой презентаций. Отклонено.

## Риски и ограничения

- Смена семантики 100% на обычных страницах: старые E2E зума и страниц нужно
  обновить; фиксированные страницы сохраняют прежнюю семантику.
- Сетка на бесконечном холсте рисуется в мировых координатах; при малом зуме
  шаг укрупняется, чтобы не рисовать миллионы точек.
- `getClientRect()` по всем объектам при «вписать» и PDF — до лимита объектов
  комнаты; приемлемо.
- Старые пометки презентаций могут сместиться (согласовано).

## Проверка

- Backend: нормализация старых страниц в `infinite`, сохранение `canvas` в
  снимке/Redis, права и границы `workspace_canvas`, координаты ±1 000 000.
- E2E: бесконечная страница — панорама за пределы старого листа, рисование там,
  «вписать» по контенту, перезагрузка; фиксированная страница — прежний лист;
  PDF — пропорции по границам объектов; презентация — холст по натуральному
  размеру слайда и восстановление страницы после выхода.
- Полная регрессия: backend, `ruff`, `black`, Playwright, `docker compose config`.
