# Дизайн: ластик только по кисти, отмена действий и блокировка элементов

Дата: 2026-11-17. Итерация P7.

## 1. Зачем

Три изменения по итогам работы с доской:

1. Ластик сейчас удаляет любой объект (штрих, фигуру, текст, картинку, блок, фрейм).
   Учителя это не устраивает: ластик должен быть именно ластиком кисти.
2. Ошибочные действия (стёртый штрих, сдвинутая фигура, удалённый фрейм) нельзя вернуть —
   нужна отмена последнего действия.
3. Учитель не может защитить готовые элементы от правок учеников: нужен замок.

## 2. Цели

- Ластик удаляет только штрихи, нарисованные кистью.
- Кнопка «Отменить» и Ctrl+Z возвращают **моё** последнее действие, включая удаление.
- Стафф ставит и снимает замок на элемент; ученик не может менять заблокированный элемент.
- Всё проверяется на сервере: замок и права не обходятся подделкой сообщений.
- Внешний вид и протокол остаются в текущем стиле проекта.

## 3. Не-цели

- Общая отмена чужих действий и «отмена для всей комнаты».
- Повтор (redo).
- Сохранение истории отмены после перезагрузки страницы, разрыва связи или перехода на
  другую страницу.
- Отмена массовой очистки доски (`clear`).
- Блокировка целой страницы или всей доски одной кнопкой.
- История версий и совместное редактирование.

## 4. Ограничения

- Один WebSocket-сервер обслуживает соединение; состояние комнаты синхронизируется через
  Redis между серверами.
- Объекты хранятся как словари без строгой схемы; `locked` — необязательное поле.
- Лимит объектов комнаты и лимит точек штриха (20 000) сохраняются.
- Клиент и сервер должны сходиться после любого события, включая отмену.

## 5. Рассмотренные подходы

### Отмена

- **Обратные события на клиенте.** Дёшево, но возврат удалённого фрейма с чужими вложениями
  теряет авторов и каскад. Требование «возвращать удалённое» исключает вариант.
- **Серверная личная история со снимками (выбрано).** Сервер хранит стек операций каждого
  пользователя на страницу: затронутые поля изменённых объектов и полные снимки удалённых,
  с авторами и позициями. `undo` применяет обратное действие и рассылает результат всем.
- **История в Redis.** Переживает реконнект, но после перезагрузки клиент всё равно теряет
  контекст, а объём и сложность растут. Отложено.

### Замок

- **Поле `locked` на объекте + серверная проверка (выбрано).** Одна новая сущность, работает
  для всех типов объектов, наследуется детьми фрейма.
- Отдельная коллекция замков — лишняя сущность и рассинхронизация с объектами.
- Только клиентская блокировка — небезопасно, сервер продолжит принимать изменения.

### Ластик

Вариантов нет: фильтр типа объекта на клиенте. Сервер не различает ластик и Delete, но
клиентский Delete и так доступен только стаффу, а права удаления проверяются как раньше.

## 6. Поведение

### 6.1. Ластик

- `Board.eraseAt` перебирает только объекты `type === "stroke"`, созданные кистью
  (`tool === "brush"`; других инструментов штрихов сейчас нет, поэтому достаточно типа).
- Права прежние: ученик стирает только свои штрихи, стафф — любые.
- Заблокированный штрих ученик не стирает; стафф стирает.
- Предпросмотр ластика больше не подсвечивает фигуры, текст, картинки, блоки и фреймы.
- Удаление остальных объектов — только выбор + Delete (стафф) или отмена своих действий.

### 6.2. Отмена

Кнопка `#undo-btn` в тулбаре и Ctrl+Z / Cmd+Z. Кнопка видна в комнате всем ролям: история
у каждого своя. При пустой истории — тост «Нечего отменять».

**Что записывается** (только успешные операции самого пользователя):

| Операция | Что сохраняется до операции |
|---|---|
| Создание штриха/фигуры/текста/картинки/блока/стрелки/фрейма | `id` созданного; для фрейма — ещё и прежние `frameId` захваченных детей |
| Перемещение объекта / фрейма | `x, y`; для фрейма — `x, y` фрейма и всех детей |
| Размер (`object_transform`) | `x, y, width, height, rotation, fontSize` |
| Правка подписи (`text_update`) | `content` |
| Фон фрейма (`frame_style`) | `fill, pattern` |
| Удаление | все каскадно удалённые объекты целиком + их индексы в списке комнаты |
| Замок/снятие замка | прежнее `locked` |

- Отмена изменения возвращает только те поля, которых касалась операция: сдвиг после чужой
  правки подписи не затрёт подпись, а отмена подписи не вернёт старые координаты.

- История — список на `(комната, пользователь, страница)`, максимум 50 записей, старые
  вытесняются. Хранится в памяти сервера, обрабатывающего соединение пользователя.
- Очищается при: смене страницы, выходе из комнаты, разрыве соединения, `clear`, удалении
  страницы, кике.
- Одна запись = одно завершённое действие: один drag, один resize, одно сохранение подписи,
  один штрих целиком (не каждая точка).
- `undo` без полезной нагрузки, с `workspaceId`. Сервер снимает верхнюю запись текущей
  страницы и применяет обратное действие:
  - создание → удалить созданное; фрейм удаляется без удаления детей (детям возвращается
    прежний `frameId`); у блока удаляются его стрелки, если они появились позже;
  - удаление → вернуть снимки на прежние позиции, с прежними авторами;
  - изменение → записать сохранённые поля обратно, не трогая остальные;
  - замок → вернуть прежнее состояние замка.
- Запись, которую нельзя применить (объект уже удалён другим, элемент заблокирован для
  ученика), пропускается, и берётся следующая. Если применимых нет — `undo_empty`.
- Результат отмены рассылается **всем, включая инициатора**, одним событием
  `objects_restored`:
  `{ removedIds: [id], objects: [{ index, object }], workspaceId }`.
  `index` — позиция в списке объектов комнаты на момент снимка; `null` для изменённых
  объектов, которые уже есть на доске. Сервер вставляет восстановленные объекты по этим
  индексам (с зажимом в границы списка). Клиент удаляет `removedIds`, затем добавляет/
  обновляет объекты в порядке события; фреймы, как и сейчас, уезжают вниз. Точный порядок
  наложения восстанавливается для восстановленной группы; объекты, созданные после удаления,
  могут оказаться под ней — визуальный край, не влияет на данные.
- Клиент применяет `objects_restored` через существующий путь обновления объекта (позиция,
  размер, подпись, фон, `frameId`) и отдельно обновляет значок замка.
- Снимки копируются при записи (не алиасы живых объектов).
- Отмена сама в историю не пишется.
- Активный штрих отменять нельзя: клиент не посылает `undo`, пока рисует.

### 6.3. Замок

- Новое сообщение `object_lock` `{ objectId, locked }`, только стафф. Broadcast
  `object_lock` `{ objectId, locked, workspaceId }` всем, включая инициатора.
- У объекта появляется `locked: true`; отсутствие поля = `false`.
- Проверка на сервере: для ученика объект заблокирован, если `locked` у него самого или у
  фрейма-родителя (`frameId`). Стафф не ограничен.
- Проверка применяется к перемещению, размеру, подписи, фону фрейма, удалению и отмене.
  Ответ — ошибка `locked` «Элемент заблокирован учителем».
- Удаление фрейма учеником запрещено, если среди детей есть заблокированный.
- Захват в новый фрейм и привязка при перемещении не выполняются для ученика, если фрейм
  заблокирован: его новый объект остаётся свободным и подвижным.
- Учитель двигает, редактирует и удаляет заблокированное; замок только для учеников.
- Замок — обычное действие учителя и отменяется его же кнопкой отмены.
- Ученик может провести стрелку между заблокированными блоками: сами блоки не меняются,
  стрелка — новый объект.
- Клиент:
  - `#lock-btn` в тулбаре с иконкой замка, виден только стаффу при выбранном объекте;
    активное состояние = объект заблокирован.
  - У заблокированного объекта поверх правого верхнего угла bbox — маленькая иконка замка
    (Konva, `listening(false)`). Видна всем.
  - У ученика для заблокированного объекта выключены drag, трансформер, двойной клик,
    Delete и ластик; попытка удаления даёт тост.
  - Замок фрейма визуально не дублируется на детях, но дети ведут себя заблокированными.

## 7. Протокол и сервер

- `schemas.py`:
  - `ObjectLock(_Message)`: `type: Literal["object_lock"]`, `objectId`, `locked: bool`.
  - `Undo(_Message)`: `type: Literal["undo"]`.
  - `ClientMessage` — добавить оба варианта.
- `ws.py`:
  - `_locked_for(user, room, obj)` — наследование замка фрейма.
  - `_ensure_editable(...)` или явные проверки рядом с `_can_edit_object` в move/transform/
    text_update/frame_move/frame_style/delete.
  - `_handle_object_lock`, `_handle_undo`.
  - `_snapshot_objects` / `_restore_objects` — общие помощники для истории.
  - История — `dict[user_id, list[Entry]]` в менеджере комнат, привязана к workspace.
  - Каскадное удаление: снимок всех `_deletion_cascade` + самого объекта, с индексами.
  - `clear` и `workspace_switch` чистят личную историю (clear — всем).
- `room_manager.py`:
  - `object_lock` — изменяющее событие: локальное применение и Redis-синхронизация.
  - `objects_restored` — изменяющее событие: удалить `removedIds`, вставить/заменить
    `objects` по индексам (с зажимом) и разослать по подпискам.
  - История отмены в Redis не синхронизируется: она принадлежит соединению пользователя.
- Ограничение по ёмкости: снимки штрихов могут быть крупными; лимит 50 записей на
  пользователя и общий лимит объектов комнаты остаются единственной защитой.
- Картинка при отмене удаления восстанавливается как объект; файл из `uploads` не удаляется
  и при отмене создания — чистка хранилища остаётся отдельной задачей.

## 8. Клиент

- `frontend/js/board.js`:
  - `eraseAt` — только штрихи.
  - `applyObjectsRestored({ removedIds, objects })` — удалить и восстановить/обновить узлы.
  - `_applyLockBadge(entry)` — иконка замка, обновление при `object_lock` и восстановлении.
  - Учёт `locked` в `canEditObject`/`canDeleteObject` предикатах (передаются из `main.js`).
- `frontend/js/main.js`:
  - `#undo-btn`, Ctrl+Z/Cmd+Z, отправка `undo`.
  - `#lock-btn` для стаффа, отправка `object_lock`.
  - обработка `object_lock` и `objects_restored`.
  - предикаты прав учитывают `locked` и замок фрейма-родителя.
- `frontend/index.html`, `frontend/css/style.css` — кнопки, панель, стили значка.
- Кнопки не перехватывают Ctrl+Z внутри полей ввода (как сейчас с клавишами).

## 9. Тесты

Backend (`backend/tests/test_board_undo_lock.py`):

- отмена создания фигуры/текста/картинки/фрейма/стрелки/штриха;
- отмена перемещения, размера, подписи, фона, замка;
- отмена удаления возвращает объекты с авторами и позициями;
- удаление фрейма и отмена возвращают фрейм и детей;
- удаление блока с arrow и отмена возвращают оба;
- отмена создания фрейма не удаляет захваченных детей;
- у каждого пользователя своя история; чужие действия не отменяются;
- пустая история → `undo_empty`; неприменимая запись пропускается;
- смена страницы, `clear` и disconnect очищают историю;
- замок: ученик не может move/transform/text/style/delete, стафф может;
- замок фрейма блокирует детей; захват в заблокированный фрейм не происходит;
- `object_lock` от ученика → `forbidden`;
- Redis: `object_lock` и `objects_restored` синхронизируют состояние двух серверов.

E2E (`e2e/tests/board-undo-lock.spec.js`):

- ластик стирает штрих и не трогает фигуру, текст, блок и фрейм;
- ученик не стирает чужой штрих;
- кнопка отмены убирает созданную фигуру и возвращает стёртый штрих;
- Ctrl+Z возвращает перемещённый объект; пустая история даёт тост;
- учитель ставит замок, ученик не может двигать/удалять/править подпись, видит значок;
- снятие замка возвращает ученику возможность двигать;
- замок фрейма не даёт ученику вытащить ребёнка.

## 10. Известные ограничения

- История отмены живёт на сервере соединения: после реконнекта, перехода на другой сервер
  или перезагрузки страницы отменять нечего.
- `clear` не отменяется.
- Снимки крупных штрихов занимают память; ограничение — 50 записей на пользователя.
- Замок не мешает ученику создать новый объект поверх заблокированного.
- Заблокированный элемент можно выделить: ученик видит рамку выделения и значок замка.
