# Блокировка для всех, размер холста и «невидимка» администратора: дизайн

**Дата:** 2026-11-18
**Статус:** решения согласованы с пользователем, дизайн на утверждении
**Пункты бэклога:**
1. Блокировка элементов работает для всех, т.е. учитель тоже не может менять элемент, пока не снимет блок.
2. Возможность создания кастомного размера рабочего пространства холста.
3. Администратора в комнате видит только учитель; администратор может снять «невидимку», тогда ученик тоже видит его в списке участников.

## 1. Замок для всех

**Сейчас.** `_locked_for` пропускает staff (`if is_staff: return False`), а на клиенте
`lockedFor`/`canEditObject`/`canDeleteObject` дают учителю и администратору обход.
Замок ставит и снимает только staff.

**Решение.** Замок запрещает изменения всем, включая staff. Доступны только выделение
и снятие замка кнопкой. Удаление, перемещение, трансформация, текст, шрифт, цвет и стиль
фрейма заблокированного объекта отклоняются; дети заблокированного фрейма тоже.

- Backend: `_locked_for(room, obj)` больше не смотрит на роль; все существующие
  проверки в обработчиках уже вызывают его, поэтому меняется одна функция и её вызовы.
- `object_lock` остаётся staff-only и намеренно не проверяет замок — иначе снять его
  было бы невозможно.
- Frontend: `lockedFor` без обхода для staff; `canEditObject`/`canDeleteObject`
  учитывают замок и для staff. Кнопка замка остаётся доступной staff.
- Отмена действий по заблокированному объекту не проходит, пока замок не снят;
  после снятия история снова работает.
- README и подсказки обновляются: замок защищает от всех изменений любого участника.

**Рассмотренные варианты.** (а) Блокировать только перемещение — не соответствует
«блокировка работает для всех» и оставляет обход через текст/размер/удаление.
(б) Запрещать всё, кроме снятия замка — выбран.

## 2. Кастомный размер холста

**Сейчас.** Ширина и высота — глобальные `Settings.board_width/height` (1600×900).
Комната, снимок и Redis размер не хранят; клиент получает его в `init` и применяет
`setBoardSize()`, который сбрасывает вид. PDF и фон слайда уже считают пропорции
от размера доски.

**Решение.** Размер задаётся **на комнату целиком** и хранится вместе с её состоянием.
Его меняет staff; изменение сразу применяется у всех участников и переживает
перезапуск/перезагрузку.

- Ограничения: целые `width`/`height` от 640 до 4000; отношение сторон от 1:4 до 4:1.
  Значения вне диапазона отклоняются как `invalid_message`.
- Хранение:
  - `Room.board: dict[str, int]`;
  - снимок `room_snapshots.board TEXT NOT NULL DEFAULT '{}'` (миграция через
    `ALTER TABLE`, как это уже сделано для `workspaces`);
  - Redis-ключ `board` в комнате (запись, восстановление, удаление, синхронизация).
- Протокол: клиент → сервер `board_resize {width, height}`; сервер проверяет staff и
  диапазон, обновляет комнату, помечает её грязной и рассылает всем
  `board_resize {width, height}`. В `init` поле `board` берётся из комнаты,
  а не из настроек.
- Клиент: staff-only кнопка «Холст» в тулбаре открывает панель с текущими значениями,
  пресетами (16:9 1600×900, 4:3 1440×1080, A4 1587×1123, квадрат 1200×1200) и полями
  ширины/высоты. «Применить» отправляет сообщение. На презентации панель скрыта.
- При получении размера доска меняет логические размеры и пересчитывает вид **без
  сброса зума** (вместо `fit()` — `layout()`); существующие объекты не масштабируются
  и не удаляются, объекты за новыми границами остаются на своих координатах.
- PDF-экспорт и фон слайда автоматически используют новые пропорции.

**Рассмотренные варианты.** (а) Размер на каждую страницу — гибче, но ломает
единые пропорции комнаты, усложняет презентации и переключение. (б) Глобальная
настройка на сервере — не даёт менять размер из интерфейса. (в) Размер на комнату —
выбран.

## 3. «Невидимка» администратора

**Сейчас.** `list_users` отдаёт всех подключённых, `user_joined`/`user_left` рассылаются
всем, курсоры летят всем. Роль и цвет есть в публичном профиле.

**Решение.** Администратор при подключении **скрыт по умолчанию**: ученики не видят его
в списке и не получают его курсор. Учителя и другие staff видят его всегда. Администратор
видит всех и себя. Кнопка-глаз снимает и возвращает «невидимку»; состояние живёт
до отключения и не запоминается.

- `ConnectedUser.invisible: bool`; при входе `role == "admin"` → `True`.
- `list_users(room, viewer)` фильтрует скрытых администраторов для не-staff;
  staff получает флаг `invisible` для бейджа. `init` и `users_state` отдают
  отфильтрованный список и `userCount`; сам администратор получает `invisible` о себе.
- Ростер синхронизируется сообщением `users_state` (`users`, `userCount`, `invisible`),
  которое отправляется каждому клиенту отдельно после входа, выхода и переключения
  видимости. Старые `user_joined`/`user_left` для списка больше не используются;
  обработчик `users_state` на клиенте заменяет список и убирает курсоры исчезнувших.
- `set_invisible {invisible}` — только для роли `admin`; сервер обновляет состояние,
  presence в Redis (флаг `hidden`), рассылает `users_state` и публикует
  `users_changed` для других инстансов.
- Скрытый администратор не рассылает курсор вообще; при переходе в скрытый режим
  всем отправляется `cursor_remove`. Рисование и права staff при этом сохраняются.
- Redis presence хранит `hidden`, поэтому `list_users` на другом инстансе фильтрует
  так же; после удалённого `users_changed` инстанс пересобирает ростер для своих клиентов.
- UI: кнопка-глаз `#invisible-toggle` в заголовке панели участников, видна только
  администратору; `aria-pressed` отражает скрытость, подпись меняется
  «Скрыть меня / Показать меня». Учитель видит администратора с пометкой «невидимка».

**Рассмотренные варианты.** (а) Скрывать только строку списка, оставляя курсор —
выдаёт присутствие. (б) Запоминать состояние в УЗ — не просили. (в) Скрыт по умолчанию,
скрыт и курсор, состояние на подключение — выбран.

## Границы и ограничения

- Новых зависимостей нет; формат истории, объектов и существующих снимков совместим
  (новые поля читаются с значениями по умолчанию).
- Размер холста и «невидимка» не меняют права на объекты сверх описанного.
- Замок меняет привычное поведение учителя — это осознанное требование бэклога.
- Старые снимки без `board` получают текущие настройки сервера.
- Презентации: размер холста меняется, но панель на презентации скрыта; слайды
  по-прежнему вписываются в доску.

## Проверка

- Backend: замок блокирует учителя и администратора (объект и ребёнок фрейма), снятие
  замка возвращает возможность правок; размер холста валидируется, сохраняется в
  снимке и Redis, рассылается всем и не сбрасывает права; скрытый администратор
  отсутствует в ростере ученика, присутствует у учителя, появляется/исчезает по
  переключателю, его курсор не доходит до ученика, presence на втором инстансе
  фильтруется.
- E2E: учитель не двигает заблокированный блок, снимает замок и двигает; учитель
  меняет размер холста, ученик видит новый размер, после перезагрузки размер сохранён;
  администратор скрыт от ученика, учитель его видит, глаз показывает его ученику и
  снова скрывает.
- Полная регрессия: backend, `ruff`, `black`, весь Playwright, `docker compose config`.
