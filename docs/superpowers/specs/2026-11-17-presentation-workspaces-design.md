# Воркспейсы-презентации: дизайн

Дата: 2026-11-17. Статус: на согласовании.

## Зачем

Учителю нужен режим урока, где на странице показана презентация: он листает
слайды и делает пометки кистью, а ученики только смотрят. Обычная доска для
этого не подходит: на ней доступны все инструменты, а слайды и пометки нужно
хранить отдельно по слайдам.

## Цели

- Новый тип воркспейса `presentation`.
- Учитель загружает PDF, сервер превращает страницы в изображения слайдов.
- Учитель переключает слайды; все участники видят один и тот же слайд.
- На презентации учителю доступна только кисть; ученик не может ничего менять.
- Пометки кистью хранятся отдельно для каждого слайда.
- Презентация переживает reconnect, смену страницы и рестарт сервера (снимок/Redis).

## Не-цели

- PPTX/Keynote и серверный LibreOffice.
- Анимации, заметки докладчика, переходы между слайдами.
- Независимое листание слайдов учениками.
- Редактирование PDF или повторная загрузка файла в существующую страницу.
- Векторный экспорт презентации в PDF.
- Автоматический перенос учеников на страницу презентации (для этого есть
  существующая кнопка «Всех к себе»).

## Выбранный подход

PDF-only. При загрузке сервер рендерит страницы PDF в JPEG шириной 1600 px
через `pypdfium2` и сохраняет их в существующем `ImageStorage` (локально или
S3). В браузер уходят только изображения слайдов; PDF.js и другие клиентские
библиотеки не нужны. Это даёт одинаковый вид у всех, простой просмотр для
ученика и не требует хранить/разбирать PDF на клиенте.

Альтернативы: PPTX через LibreOffice (+~400 МБ образу, медленная конвертация),
клиентский PDF.js (лишняя зависимость и разный рендер), ручная загрузка
картинок по слайдам (неудобно). Отклонены.

## Модель данных

Обычный воркспейс остаётся `{id, name, position}`. Презентация добавляет поля:

```json
{
  "id": "ws_...",
  "name": "Урок 5",
  "position": 2,
  "kind": "presentation",
  "slides": ["/uploads/abc-1.jpg", "/uploads/abc-2.jpg"],
  "slideIndex": 0
}
```

- `slides` — упорядоченный список URL изображений (1–80).
- `slideIndex` — общий для комнаты текущий слайд; меняет только staff.
- Штрихи презентации — обычные stroke-объекты с дополнительным полем
  `slide` (0-based). Объекты других типов на презентации не создаются.
- `Room.objects_for(workspace_id)` для презентации возвращает объекты только
  текущего слайда; `init`/`workspace_state`/`presentation_slide` используют его.
- Снимки и Redis хранят воркспейс целиком; `normalize_workspaces` сохраняет
  `kind/slides/slideIndex` и чинит некорректные значения.
- Удаление презентации удаляет её объекты, но не чистит изображения слайдов
  (отдельная задача очистки хранилища).

## Загрузка

`POST /api/presentations` (multipart, staff, same-origin):

- принимает только PDF (`%PDF-`, `application/pdf`);
- лимит `MAX_PRESENTATION_MB` (40 МБ) и `MAX_PRESENTATION_SLIDES` (80);
- рендерит каждую страницу в JPEG 1600 px по ширине, quality 88;
- сохраняет через `ImageStorage.save`, возвращает
  `{slides: [urls], pageCount}`;
- некорректный/битый PDF, превышение лимитов — 400/413/415 с русским текстом.

Клиент после загрузки отправляет существующий `workspace_create` с
`kind="presentation"` и `slides`. Сервер проверяет, что каждый URL существует
в `ImageStorage`, создаёт воркспейс, рассылает `workspace_created` и
переключает создателя на него. Имя — имя файла без `.pdf` (до 60 символов).

## WebSocket

- `WorkspaceCreate` расширяется: `kind: "page" | "presentation" = "page"`,
  `slides: list[str]` (не более 80, URL-паттерн загрузок).
- Новый клиентский тип `presentation_slide {workspaceId?, slideIndex}`.
- Новое серверное событие `presentation_slide {workspaceId, slideIndex, objects}`.
- `workspace_state` получает `slideIndex` (для презентации); `init.workspaces`
  уже содержит `slides/slideIndex`.
- Ответ на смену слайда рассылается всем, включая инициатора.
- Redis: событие `presentation_slide` обновляет `slideIndex` в
  `workspaces`-хэше; `_apply_remote_event` меняет индекс у всех инстансов.
- `WORKSPACE_SCOPED_EVENTS` пополняется `presentation_slide`.

## Права и ограничения

Сервер, а не только UI:

- На презентации разрешены только `stroke_start/point/end` (кисть), `cursor`,
  `presentation_slide` (staff) и служебные `workspace_*`/`kick`.
  Остальные объектные сообщения и `clear`/`undo` отклоняются ошибкой
  `presentation_view_only`.
- `stroke_start`: staff и `tool === "brush"`, иначе `presentation_brush_only`.
- Ученик не может менять слайд; `presentation_slide` от ученика — `forbidden`.
- Ученик не может рисовать: его `stroke_start` отклоняется.
- Клиент скрывает все инструменты, кроме кисти у staff; ученику оставляет
  только просмотр (`setInteractive(false)`), прячет кисть, цвета, ширину,
  изображения, отмену, замок, очистку и PDF.
- Двойной клик, Delete/F2/Ctrl+Z и вставка из буфера на презентации отключены.
- Смена слайда финализирует активный штрих учителя до рассылки события.

## Интерфейс

- В панели страниц у staff появляется кнопка «+ Презентация» рядом с
  «+ Страница»; она открывает выбор PDF и после загрузки создаёт страницу.
- Страницы-презентации помечаются в списке значком/подписью.
- Внизу доски — контролы `‹  3 / 12  ›`: у staff кнопки активны, у ученика
  виден только счётчик.
- Учитель листает стрелками на экране и клавишами `←`/`→` (когда фокус не в
  поле ввода).
- Слайд рисуется в фоне доски с сохранением пропорций (contain, по центру,
  белые поля). Сетка на презентации скрыта.
- При смене слайда клиент заменяет объекты доски объектами нового слайда.

## Тесты

Backend:

- загрузка PDF (staff) → слайды сохранены, URL доступны; ученик получает 403;
- битый файл/не PDF/превышение размера и числа слайдов отклоняются;
- `workspace_create` с presentation создаёт страницу с `slides/slideIndex`;
- `presentation_slide` переключает индекс и рассылается всем; ученику нельзя;
- на презентации ученик не может рисовать, staff не может добавить фигуру/текст/
  изображение/удалить/очистить/отменить; кисть staff работает;
- `workspace_state`/`objects_for` отдают только штрихи текущего слайда;
- Redis: `presentation_slide` и метаданные презентации доезжают между
  менеджерами; снимок сохраняет `slides/slideIndex` и штрихи слайдов.

E2E:

- учитель загружает двухстраничный PDF, страница появляется, слайд виден;
- учитель рисует на слайде 1, переключает на слайд 2 — пометки скрыты,
  возвращается на слайд 1 — пометки на месте;
- ученик видит слайд и пометки, но не видит инструментов и не может рисовать;
- у ученика нет кнопок листания и загрузки презентации.

## Риски

- `pypdfium2` + Pillow увеличивают образ и требуют пересборки; конвертация
  больших PDF ограничена 40 МБ/80 страниц.
- 80 слайдов по 1600 px занимают заметное место в хранилище; картинки не
  удаляются при удалении страницы (отложенная очистка).
- Штрихи на слайдах — растровые пометки, как и вся доска; экспорт/поиск текста
  не предусмотрены.
- Ученик может вручную переключиться на другую страницу (существующее
  поведение); для совместного просмотра используется «Всех к себе».
