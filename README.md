# Онлайн-доска для уроков

Совместная интерактивная доска для онлайн-уроков: FastAPI + WebSocket + Konva.js.
Пользователи работают по учётным записям; учитель создаёт комнаты и выдаёт к ним доступ
своим ученикам, администратор подтверждает УЗ и видит все комнаты.

## Возможности

- Регистрация по имени, логину и паролю; вход только после подтверждения администратором.
- Роли: **ученик**, **учитель**, **администратор** (функционал учителя + управление УЗ +
  доступ ко всем комнатам). Учителей назначает администратор; он создаётся при первом запуске.
- Комнаты: уникальный id и название, владелец-учитель. Учитель создаёт, переименовывает и
  удаляет свои комнаты, выдаёт и отзывает доступ конкретным активным ученикам.
- Ученик видит и открывает только комнаты, куда его добавили; гостевого входа нет.
- Cookie-сессии (`wb_session`, HttpOnly), проверка статуса УЗ и роли на каждом REST-запросе
  и WS-подключении; блокировка, отзыв доступа и удаление комнаты выкидывают из неё сразу.
- Кисть, ластик, прямоугольник, круг, линия, стрелка, текст.
- Блок-схемы: процесс, решение, начало/конец с подписями; стрелки прилипают к блокам и
  перестраиваются при их перемещении и изменении размера.
- Фреймы: рабочая область с рамкой и фоном (заливка, линии или клетка); брошенные внутрь
  элементы прикрепляются и двигаются вместе с фреймом.
- Выбор и перемещение объектов (ученик — свои, учитель и администратор — любые); картинку
  можно двигать сразу после вставки.
- Ластик стирает только штрихи кисти (учитель — любые, ученик — свои).
- Отмена (`Ctrl+Z` или кнопка) возвращает моё последнее действие, включая удаление;
  история личная и постраничная, живёт до перезагрузки или выхода — после возврата
  на страницу отмена снова работает. На презентации
  учитель отменяет последний штрих текущего слайда — пометки других слайдов не трогаются.
- Блокировка: staff запирает элемент от любых изменений — ученика, учителя и
  администратора; замок наследуется детьми фрейма, новые объекты в заблокированный
  фрейм не захватываются, а снять замок (кнопкой или отменой) может только staff.
- Масштабирование и поворот фигур, текста и изображений через Transformer.
- Локальный масштаб рабочей области 10–400% и панорамирование: кнопки `− 100% +`
  в углу доски, `Ctrl/Cmd+колесо` — зум вокруг курсора, колесо — прокрутка,
  протяжка пустого места в режиме «Выбор», средняя кнопка или `Space+протяжка` —
  перетаскивание холста, на планшете два пальца — зум и панорама (один палец рисует),
  клавиши `+`/`-`/`0`. Вид у каждого свой и не меняет доску у других участников.
- Обычные страницы бесконечные: 100% — реальный масштаб, панорама не ограничена
  краями, «Вписать» (`0`) показывает все объекты с отступом. Фиксированный лист
  с пресетами 16:9, 4:3, A4, 1:1 включается в «Ещё → Холст страницы» и запоминается
  для конкретной страницы. Объекты при смене режима не масштабируются.
- Презентации подстраивают холст под натуральный размер слайда: без полей, сетки
  и лишних краёв; после выхода страница возвращается к своему режиму.
- Редактирование текста двойным кликом или клавишей `F2`.
- Пять системных шрифтов для текста (обычный, с засечками, моноширинный, рукописный,
  узкий): список в тулбаре задаёт шрифт нового текста и меняет выделенный; блоки
  схем, стрелки и фреймы сохраняют свой шрифт.
- Загрузка изображений через `POST /api/upload` (локально или в S3-совместимом хранилище).
- Вставка картинок и скриншотов из буфера обмена (`Ctrl+V`/`Cmd+V`), в том числе
  нескольких сразу; в полях ввода и редакторе текста вставка не перехватывается.
- Экспорт текущей страницы в PDF (учитель/администратор): область по границам
  содержимого с отступом, без сетки, курсоров и выделения; текст в PDF растровый.
- Курсоры участников с троттлингом.
- Администратор по умолчанию невидим для учеников: они не видят его в списке и не
  получают его курсор, а учителя и staff видят всегда. Кнопка-глаз в панели участников
  показывает администратора ученикам и снова скрывает.
- Очистка доски, удаление объектов и отключение участника — только учитель/администратор.
- Несколько страниц (воркспейсов) в комнате: список видят все, каждый переключается сам.
- Панели «Страницы» и «Участники» сворачиваются в узкую полоску кнопкой в заголовке;
  состояние запоминается в браузере, доска занимает освободившееся место без сброса зума.
- Презентации: учитель загружает PDF (до 40 МБ, 80 слайдов), листает слайды
  и рисует на них только кистью; ученик видит текущий слайд и пометки, но не
  может рисовать, менять слайд или пользоваться инструментами. Пометки хранятся
  отдельно для каждого слайда.
- Учитель создаёт, переименовывает, удаляет и меняет порядок страниц; переносит одного,
  нескольких или всех учеников на свою текущую страницу. Черновик текста сохраняется на
  старой странице.
- Синхронизация в реальном времени: append-only + last-write-wins.
- Переподключение с exponential backoff и восстановлением снимка через `init`.
- Снимки доски в SQLite: периодически и при опустении комнаты; восстановление после рестарта.
- Redis Pub/Sub и общее состояние комнат для нескольких инстансов (опционально).
- Ограничение частоты сообщений на сервере, валидация всех WS-сообщений через Pydantic.
- Наблюдаемость: `/metrics` (Prometheus), JSON-логи с request-id, Sentry, `/health/ready`.

```bash
python -m venv .venv
# Windows
.venv\Scripts\pip install -r backend\requirements-dev.txt
# Linux/macOS
# source .venv/bin/activate && pip install -r backend/requirements-dev.txt

copy .env.example .env        # Windows (Linux: cp .env.example .env)
```

Запуск из папки `backend`:

```bash
cd backend
..\.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

Откройте <http://127.0.0.1:8000>.

- Администратор: логин/пароль из `ADMIN_LOGIN`/`ADMIN_PASSWORD` (по умолчанию `admin` /
  `admin-change-me` — смените в админской панели). Создаётся при первом запуске.
- Новый пользователь регистрируется на сайте и ждёт подтверждения администратора; все
  регистрируются учениками.
- Учитель создаёт комнату и в диалоге «Доступ» добавляет нужных учеников.
- Прямая ссылка `/?room=<id>` работает только у того, кому выдан доступ.

## REST API (кратко)

- `POST /api/register {login, name, password}` → 201 `{status: "pending"}`.
- `POST /api/login {login, password}` → cookie-сессия, `{user, permissions, board}`;
  `pending`/`rejected`/`blocked` → 403 с кодом статуса.
- `POST /api/logout`, `GET /api/me`.
- `GET /api/rooms` — свои комнаты (ученику — выданные); `GET /api/rooms/all` — все комнаты
  (админ); `GET /api/rooms/{id}` — комната при наличии доступа.
- `POST /api/rooms {name}`, `PATCH /api/rooms/{id}`, `DELETE /api/rooms/{id}` — учитель/админ.
- `GET|PUT /api/rooms/{id}/access` — список доступа (полная замена списка).
- `GET /api/users?q=` — каталог активных учеников для выдачи доступа (учитель/админ).
- `GET /api/admin/users`, `PATCH /api/admin/users/{id}`, `POST /api/admin/users/{id}/password` —
  только администратор. Блокировка/смена роли/сброс пароля удаляют сессии и выкидывают из комнат.
- Ошибки: `{detail: {code, message}}`; изменяющие запросы проверяют `Origin` (CSRF).

Доступ к комнате: администратор; владелец-учитель; либо активный пользователь из
`room_access`. Все проверки — на сервере.

## Протокол WebSocket (кратко)

`/ws/{room_id}?workspace=<id>` — авторизация по cookie `wb_session`; query-токена нет.
Сервер проверяет сессию, активность УЗ, существование комнаты и доступ, затем присылает
`init` (участники, страницы, текущая страница, объекты только этой страницы, права, размер
доски) и транслирует события всем, кроме отправителя. `workspace` необязателен.

Коды закрытия: `4400` некорректный id комнаты, `4401` нет/просрочена сессия, `4403` нет
доступа или выкинут, `4404` комната не найдена, `4409` сессия заменена.

Клиент → сервер: `stroke_start`, `stroke_point`, `stroke_end`, `shape_add`, `text_add`,
`image_add`, `connector_add`, `frame_add`, `frame_move`, `frame_style`, `object_update`,
`object_transform`, `text_update`, `object_delete`, `object_lock`, `undo`, `cursor`, `clear`,
`kick`, `workspace_switch`, `workspace_create`, `workspace_rename`, `workspace_delete`,
`workspace_reorder`, `workspace_pull`, `workspace_move_ack`, `presentation_slide`.

Сервер → клиент: `init`, `user_joined`, `user_left`, `stroke_*`, `shape_add`, `text_add`,
`image_add`, `connector_add`, `frame_add`, `frame_captured`, `frame_moved`, `frame_style`,
`object_update`, `object_transform`, `text_update`, `object_delete`, `object_lock`,
`objects_restored`, `presentation_slide`, `cursor`, `cursor_remove`, `workspace_state`,
`workspace_created`, `workspace_renamed`, `workspace_reordered`, `workspace_deleted`,
`workspace_prepare_move`, `workspace_moved`, `clear`, `error`, `kicked`.

Дополнительно:

- `object_update` — перемещение объекта (автор или staff); несёт `frameId`, если объект
  прикреплён к фрейму или открепился.
- `object_transform` — resize/rotate (`x`, `y`, `width`, `height`, `rotation`, `fontSize`);
  блоки схемы и фреймы не поворачиваются.
- `text_update` — изменение содержимого текста или подписи блока схемы (автор или staff).
- `object_lock` — только staff; ставит и снимает замок. Замок наследуется детьми фрейма:
  ученик не может двигать, масштабировать, переподписывать, стилизовать или удалять
  заблокированный объект; новый объект в заблокированный фрейм не захватывается.
- `undo` — отменить моё последнее действие. История личная и серверная (до 50 записей):
  смена страницы, `clear`, переподключение, кик и удаление страницы её очищают.
  Результат приходит всем как `objects_restored` `{removedIds, objects: [{index, object}],
  workspaceId}`.
- `connector_add` — стрелка между двумя блоками; рассылается всем, включая отправителя;
  удаление блока каскадно удаляет его стрелки.
- `frame_add`, `frame_captured`, `frame_moved`, `frame_style` — создание фрейма, захват
  существующих объектов, перемещение фрейма с детьми и смена фона. Привязка к фрейму
  считается по якорю (центр фигуры/картинки/блока, левый верхний угол текста); её можно
  потерять, вытащив объект за пределы фрейма.
- `kick` — отключение участника; отзыв доступа, блокировка, смена роли и удаление комнаты
  приходят как `kicked` с причиной.
- `stroke_end` несёт полный объект штриха, чтобы опоздавшие и переподключившиеся
  клиенты не теряли линию.
- `seq` присваивается сервером при финализации объекта.
- `workspaceId` есть у каждого объектного, курсорного и `clear`-события; сервер доставляет
  такое событие только участникам этой страницы.
- `workspace_state` — `{workspaceId, objects, stateVersion}`: снимок страницы после
  переключения; применяется только более новый `stateVersion`.
- `workspace_prepare_move` → `workspace_move_ack` → `workspace_moved` + `workspace_state` —
  двухфазный перенос: клиент сохраняет черновик текста и финализирует штрих, затем
  подтверждает; если ack не пришёл за `WORKSPACE_MOVE_TIMEOUT_SECONDS`, перенос выполняется
  принудительно.
- Первая страница — `ws_default` («Страница 1»); лимит объектов и `seq` общие на комнату.

## Docker

```bash
docker compose up --build
```

Приложение: <http://127.0.0.1:8000>, S3 (SeaweedFS): <http://127.0.0.1:9000>,
UI кластера SeaweedFS: <http://127.0.0.1:9333>. Ключи по умолчанию —
`whiteboard` / `whiteboard-secret` (`S3_ACCESS_KEY` / `S3_SECRET_KEY`).
Compose поднимает Redis и SeaweedFS, поэтому проверяются общее состояние комнат
и S3-загрузки. Перед публикацией задайте `ADMIN_PASSWORD` (или смените пароль в админке),
`COOKIE_SECURE=true` и ключи S3.

Если локальный `uvicorn` уже использует `./data`, остановите его перед запуском
compose: SQLite в режиме WAL не работает через bind mount из двух процессов
одновременно (появится `disk I/O error`).

Производственный деплой с автоматическим HTTPS, Caddy, бэкапами и масштабированием —
см. [docs/deploy.md](docs/deploy.md). Деплой на VDS рядом с уже работающими
контейнерами за общим reverse proxy и через GitHub Actions —
см. [docs/deploy-vds.md](docs/deploy-vds.md).

## Ограничения

- Нет самостоятельной смены пароля (пароль меняет администратор), нет восстановления по email.
- Нет CRDT/OT: одновременное редактирование одного объекта не поддерживается.
- Штрихи нельзя перемещать, масштабировать или поворачивать.
- Нет чата, записи урока и домашних заданий.
- Konva подключается с CDN; для закрытого контура файл нужно положить в `frontend/vendor/`.
- SQLite подходит для одного-двух инстансов; при большем масштабе нужен Postgres.
